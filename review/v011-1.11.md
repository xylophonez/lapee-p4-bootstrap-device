## Native boot composition and recipient roles

Startup puts native `p4@1.0` first in the inherited request hook list, appends
its response processor and GC hook, and preserves the other handlers. The
legacy bootstrap request/response exports remain for older callers; the new
startup does not install them. Both payment and P4 use the canonical RC4 path
`/~node-process@1.0/ledger`.

The internal `p4-recipient`, deposit address and ledger admin are the node
wallet. External `ao-payment-withdraw-recipient` is the explicit canonical
`bundler-beneficiary` supplied by operator/UI configuration. The beneficiary
must be nonzero and different from the node wallet. Existing pricing,
recharging-ledger/fallback selection and operator exemption lists remain
available. Existing submission/mainnet/node endpoint overrides and explicit
`ao-payment-auto-withdraw=false` are preserved rather than replaced by public
profile defaults. No new configuration surface or policy restriction.
